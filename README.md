# Burn Rate — харнесс для openJiuwen Challenge 2026

Харнесс решает задачи четырёх типов (math, search, data_analysis, coding) в пределах бюджета токенов
и заранее оценивает, сколько токенов стоит каждая задача. Большую часть задач он решает вообще без
нейросети, остальные — облегчённым агентом openJiuwen, в порядке «баллы × вероятность успеха ÷
прогноз расхода».

> Цифры — из нашего журнала замеров (`docs/journal.md`).

## Как это работает

```
задачи ──► фаза A: решение без нейросети ──► answer.txt (0 токенов)
             │  разбор условий по шаблонам («уверен или молчит»)
             │  починка кода перебором (APR) с защитой от подгонки под тесты
             │  отсев нерешаемых задач
             ▼
           признаки задачи ──► оценщик расхода (harness/cost_model.json)
             ▼
           фаза B: очередь «баллы × p ÷ прогноз», резерв бюджета под задачи в работе
             ▼
           облегчённый агент openJiuwen (DeepAgent) + наши инструменты ──► answer.txt
```

**Фаза A — без нейросети.** Решатели (`harness/solvers/`) разбирают условие строгими шаблонами и
считают ответ сами. Главное правило — «уверен или молчит»: если хоть одно предложение условия не
понято, задача уходит агенту, а не получает догадку. То же для «нерешаемых»: задачу отбрасываем, только
если точно знаем, что данных нет. Код чинится перебором мутаций AST; починки, похожие на подгонку под
видимые тесты (нейтрализованная константа `+ 0`, подобранный индекс `ys[1]`), отдаются агенту, потому что
баллы начисляются по скрытым тестам.

**Фаза B — агент openJiuwen.** `harness/oj_agent.py` создаёт `create_deep_agent` с коротким системным
промптом и 1–2 своими инструментами (`python` для math и data_analysis, `update_code` для coding). Один
запрос — около 1 000 символов вместо ~38 000 у стандартного code agent. Каждый вызов модели проходит
через обёртку `BudgetModel`: она списывает расход с общего бюджета и с бюджета задачи, резервирует
бюджет, не даёт параллельным задачам выйти за предел и повторяет запрос при ошибках прокси.

**Досрочная остановка.** Агент останавливается, как только цель достигнута: тесты прошли
(`update_code`) или скрипт напечатал `FINAL: ответ`. Это убрало лишний вызов модели: 6 242 → 4 510
токенов на cmp40 при той же точности.

## Оценщик расхода

### Зачем он нужен

За каждую задачу дают от 1 до 5 баллов, и эти баллы раздаются случайно: дорогая задача может стоить
1 балл, а дешёвая — 5. Если бюджета не хватает на всё, выгоднее сначала брать задачи, где за каждый
балл платишь меньше всего токенов. Для этого нужно знать цену задачи **до** того, как её решать.
Это и делает оценщик. Организаторы прямо назвали такую оценку сутью хакатона.

### Как он угадывает цену

Как опытный мастер, который по фото смотрит на поломку и называет цену ремонта, ещё не открыв ящик с
инструментами. Оценщик смотрит на задачу и замечает то, от чего зависит объём работы модели:

- **coding** — сколько тестов падает, как длинен их вывод и сколько кода: больше ошибок и кода — больше
  модели читать и писать;
- **math** — сколько шагов в условии: длиннее программа, которую напишет модель;
- **data_analysis** — сколько столбцов в таблице: шапка таблицы целиком идёт в запрос;
- **search** — насколько длинный вопрос: длинная цепочка связей — больше текста из базы знаний.

Всё это считается по файлам задачи за доли секунды и без единого вызова модели (`harness/features.py`).

### Как мы его учили

1. Сгенерировали 600 своих задач разного размера — от простых до заметно сложнее примеров
   организаторов (`tools/gen_tasks.py --spread 1`).
2. Решили их все через модель и записали, сколько токенов ушло на каждую. Записываем только числа —
   текст ответов модели не храним и ни на чём не учимся (`data/traces/`).
3. Для каждого типа задач нашли простую формулу вида «цена = база + вес × признак + …»
   (`tools/fit_cost_model.py`). Формула лежит в маленьком файле `harness/cost_model.json`.

### Насколько он точен

Проверяли честно — на задачах, которые оценщик при обучении не видел.

- Если просто брать «среднюю цену задачи этого типа», ошибаешься в среднем на 19 токенов.
- Наш оценщик ошибается на 7 — **в 2.6 раза точнее**.
- Пробовали и более сложную модель (градиентный бустинг): точнее не стало. Оставили простую формулу —
  её можно прочитать глазами, и ей не нужны лишние библиотеки в контейнере.

### Что это даёт

Когда бюджета не хватает, харнесс с оценщиком набирает почти столько же, сколько «оракул», заранее
знающий настоящую цену каждой задачи (93–100%). При бюджете 1000 токенов — 69 баллов против 50, если
брать задачи просто по числу баллов, и 27 при случайном порядке. На настоящем прокси: 70 баллов против 30
у случайного порядка при одном и том же бюджете.

Во время прогона оценщик ещё и подстраивается: если задачи какого-то типа выходят дороже прогноза, он
понемногу поднимает цену для остальных задач этого типа.

## Почему так

- **Модель:** сравнили все разрешённые варианты на 60 задачах (`tools/compare_llms.py`):
  `qwen3.8-27b-noreason` — 155/160 и 6 649 токенов; варианты с рассуждениями точнее не стали, а тратят в
  2–4 раза больше.
- **Без нейросети везде, где это надёжно** — такие задачи стоят 0 токенов.
- **Проверка на чужом оформлении** (`tools/make_variants.py`): тесты в стиле pytest и в подпапках
  (`harness/testrun.py`), CSV с `;`, база знаний не в `kb/`.

## Как запустить

### Как у жюри (Docker)

```bash
docker build -t hack:latest .                     # ~3 мин с нуля, образ 1,4 ГБ (лимиты: 1000 с, 4 ГБ)
export LLM_BASE_URL=https://api.neuraldeep.ru/v1 LLM_API_KEY=<ключ>
BUDGET=100000 NETWORK=bridge tools/jury_run.sh examples/tasks
```

`tools/jury_run.sh` копирует задачи во временную папку, запускает образ с флагами из регламента
(`--read-only`, `--tmpfs /tmp`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--pids-limit 512`,
`--memory 16g`, таймаут 1 час) и проверяет ответы `tools/score.py --strict`. Код выхода не 0, если прогон
упал, ответ неверный или невыполнимая задача получила ответ. Без ключа и с `NETWORK=none` решается всё,
что можно решить без модели (на примерах организаторов — 20/20 за 0 токенов). Переопределить можно только
`IMAGE`, `NETWORK`, `CPUS` (по умолчанию не больше 4), `MEMORY`, `TIMEOUT`; в Git Bash на Windows ещё
`PYTHON=python`.

Сам запуск у жюри:

```bash
docker run ... --entrypoint python hack:latest /app/run_agent.py --tasks-dir /data/tasks
```

### Без Docker

```bash
pip install -r requirements.txt
python run_agent.py --tasks-dir examples/tasks
python tools/score.py examples/tasks
```

### Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | — | прокси организаторов; без них — только решения без модели |
| `BUDGET` | не задан — бюджет не ограничен | бюджет в выходных токенах (10 входных = 1 выходной); у жюри 100 000 |
| `OUT` | — | файл, куда дублируются все ответы (страховка, если в папку задач нельзя писать) |
| `FAST_PATH` | `1` | `0` — всё через модель (для замеров) |
| `ORDER` | `est` | порядок задач для модели: `est` (баллы × p ÷ прогноз), `reward`, `random` |
| `TIME_LIMIT_S` | `3300` | после этого новые задачи не берутся (за 60 с до конца — уже нет) |
| `PARALLEL`, `MAX_CONCURRENT` | `5`, `3` | задач в работе и одновременных запросов к прокси |
| `TRAJ_PATH` | `/tmp/trajectories.jsonl` | куда писать трассы (только числа) |

Ответ записывается в `answer.txt` рядом с `task.json` сразу после решения; для невыполнимой задачи файл не
создаётся. Если в папку задачи писать нельзя, ответ уходит в `OUT` и в лог строкой `ANSWER <задача> <ответ>`.

### Проверки перед сдачей

```bash
ruff check . && pytest -q                                   # ~260 тестов
tools/jury_run.sh examples/tasks                            # 20/20
python tools/final_eval.py --out /tmp/final --sets 2        # как у жюри, 2 набора по 100 задач, с ключом
```

## Структура

| Путь | Что там |
|---|---|
| `run_agent.py` | точка входа |
| `harness/runner.py` | планировщик: фазы A и B, бюджет задач, трассы |
| `harness/solvers/` | решатели по типам задач, починка кода перебором |
| `harness/oj_agent.py` | агент openJiuwen, учёт бюджета, инструменты |
| `harness/estimator.py`, `harness/features.py`, `harness/cost_model.json` | оценщик расхода |
| `tools/` | генератор задач, проверка ответов, сбор трасс, обучение и проверка оценщика |
| `data/traces/` | трассы для обучения оценщика (только числа) |
| `tests/` | тесты (`pytest -q`) |
